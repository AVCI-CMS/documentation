# API Keys

**Menu Path:** `Workspace > Settings > Authority > API Keys`

:::info Permission Requirements
To view and manage API keys, you must have the **workspace:manage** permission.
:::

The API Keys module allows you to integrate your workspace with storefronts, mobile applications, and server-side services securely using AVCI CMS's `x-avcicms-*` header standard and dual-key architecture.

## Credentials & Headers

### 1. Client ID (`x-avcicms-client`)
- **Identifier:** Your Client ID is the public UUID identifier for your workspace. Send it in the `x-avcicms-client` header on every external API request to route traffic to your tenant.
- **Safety:** Public and safe to use in browser bundles and mobile apps.

### 2. Publishable Key (`x-avcicms-api-key`)
- **Format:** `pk_live_...`
- **Scope:** Safe for browsers and mobile applications. Grants public read access and anonymous view logging only.
- **Rotation:** Click the inline **Rotate** icon inside the key field to generate a new Publishable Key. Generating a new key immediately invalidates the previous one.
- **Timestamps:** Creation and last-used dates are displayed in the card header.

### 3. Secret Key (`x-avcicms-secret-key`)
- **Format:** `sk_live_...`
- **Scope:** Reserved for server-side operations (SSR, backend services, cron jobs, and webhooks).
- **One-Time Visibility:** Newly generated keys are displayed in plain text **only once** inside the confirmation modal. Copy and store the key securely; afterwards it is shown masked.
- **Rotation:** Click the inline **Rotate** icon inside the key field to rotate the Secret Key immediately if compromised.

> [!WARNING]
> **Security Recommendation:** Never store `x-avcicms-secret-key` (`sk_live_...`) in client-side code or `NEXT_PUBLIC_*` environment variables. Always use `x-avcicms-client` + `x-avcicms-api-key` in browsers, and restrict `x-avcicms-secret-key` strictly to secure server environments.

### 4. Quick Start Template
Copy the ready-to-use environment variable block directly from the Quick Start card to configure your Next.js or Node.js project.

## Common Issues

- **Issue:** API requests return `401 Unauthorized` or `403 Forbidden`.
- **Solution:**
  - For public/browser calls, verify both `x-avcicms-client` and `x-avcicms-api-key` (`pk_live_...`).
  - For server-side calls requiring secret access, verify `x-avcicms-client` and `x-avcicms-secret-key` (`sk_live_...`).
  - If a key was rotated, update your deployment environment variables with the latest value.
